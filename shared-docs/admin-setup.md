# 어드민 계정 설정

어드민은 기존 로그인 화면으로 로그인하며 대시보드에서 전체 환자의 저장된 분석 결과를 검색하고 상세 결과를 열 수 있습니다. 결과가 없는 환자는 결과 목록에 표시되지 않습니다. 계정 관리나 결과 수정·삭제 권한은 추가하지 않습니다.

| 역할 | 결과 조회 범위 | 상세 정보 |
| --- | --- | --- |
| patient | 본인 계정에 저장된 결과 | 기존 환자용 정보 |
| doctor | 전체 결과 (기존 동작 유지) | 환자 식별자, 모델별 점수 등 포함 |
| admin | 전체 결과 | 의사와 동일한 상세 정보 |

## 적용 순서

1. Supabase SQL Editor에서 [스키마 SQL](schemas/supabase-analysis-results.sql)을 실행합니다. 기존 profiles 테이블의 역할 제약과 결과 조회 정책도 갱신됩니다.
2. Supabase Authentication의 사용자 관리에서 어드민 전용 계정을 생성하거나 초대합니다. 비밀번호는 코드나 SQL에 넣지 않습니다. 기존 계정을 지정할 수도 있습니다.
3. 해당 계정의 User UID를 확인하고 SQL Editor에서 아래 SQL의 UUID를 실제 UID로 바꿔 실행합니다. 예시 UUID 그대로 실행하지 않습니다.

```sql
insert into public.profiles (id, role)
values ('00000000-0000-0000-0000-000000000000'::uuid, 'admin')
on conflict (id) do update
set role = excluded.role, updated_at = now();
```

4. 변경한 백엔드와 프론트를 실행한 뒤 해당 계정으로 로그인합니다. 대시보드의 `전체 환자 분석 결과`에서 다른 계정의 저장된 결과와 상세 정보가 조회되는지 확인합니다.
5. 일반 환자 계정에서는 본인 결과만 조회되는지 확인합니다.

최신 스키마 SQL은 기존 Auth 사용자를 `profiles`에 환자로 등록하고, 분석 결과에 `created_by`와 `patient_user_id`를 추가합니다. 역할 및 결과 배정 기능을 사용하기 전에 스키마 SQL 전체를 다시 실행해야 합니다.

일반 사용자는 자신의 patient 프로필만 등록할 수 있으며 역할을 변경할 수 없습니다. 백엔드는 사용자가 수정할 수 있는 회원정보가 아닌 profiles 테이블에서 역할을 읽습니다. DB의 RLS도 의사·어드민에게만 다른 계정의 결과 조회를 허용합니다. 프론트에 service_role 키를 설정하지 않습니다.

조회는 100건씩 나눠 전체 결과를 모읍니다. 데이터가 많아지면 목록 페이지 단위 조회와 별도 상세 조회로 확장해야 합니다.

이 문서와 코드를 반영하는 것만으로 운영 DB에 계정이 생성되거나 권한이 부여되지는 않습니다. 위의 DB 적용과 계정 지정 절차가 필요합니다.
