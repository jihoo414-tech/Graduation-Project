# Cox / LASSO-Cox PDF 참고 정리

## 문서 목적
이 문서는 아래 두 PDF에서 우리 졸업 프로젝트에 **직접 도움이 되는 내용만** 추려 정리한 참고 문서다.

대상 PDF:
1. `cox 기반 생존분석 모델 논문.pdf`
2. `lasso cox regression pipeline.pdf`

핵심 초점:
- Cox 모형을 문서/발표/설계에서 어떻게 설명하면 좋은가
- LASSO-Cox를 feature selection 단계에서 어떻게 위치시키면 좋은가
- 우리 프로젝트에서 그대로 참고할 수 있는 분석 절차와 주의점은 무엇인가

## 1. 첫 번째 PDF(석사논문)에서 문서화할 만한 포인트
### 1-1. Cox 모형은 세미파라메트릭으로 설명하는 것이 적절함
논문은 Cox 비례위험모형이 **생존시간의 분포형태를 직접 가정하지 않는 점** 때문에 비모수적 성격을 가지지만,
회귀계수를 모형 기반으로 추정한다는 점에서 **세미파라메트릭(semi-parametric)** 으로 설명된다고 정리한다.

우리 프로젝트 문서에는 아래처럼 쓰는 것이 좋다.

> Cox 비례위험모형은 기저위험함수의 구체적 분포를 직접 가정하지 않으면서 공변량의 효과를 회귀적으로 추정하는 세미파라메트릭 생존모형이다.

이건 기존 외부 참고문서(STHDA/Sticky-AI)와도 잘 맞고, 너무 단순한 “비모수 모형” 설명보다 더 정확하다.

### 1-2. 단변량 → 다변량 → 간명한 최종모형 흐름이 중요함
논문은 적절한 Cox 모형 탐색 순서를 다음처럼 잡는다.
- 먼저 각 예측변수를 하나씩 보는 **단변량 모형**
- 이후 중요한 변수들을 동시에 넣는 **다변량 모형**
- 마지막으로 **해석 가능한 간명한 최종모형** 선택

우리 프로젝트에서도 이 흐름은 그대로 가져가기 좋다.

> 권장 분석 순서: 단변량 Cox 탐색 → 다변량 Cox 적합 → 해석성과 성능을 함께 고려한 최종 모형 선택

### 1-3. -2 log L 기반의 모형 비교 사고방식은 문서화 가치가 있음
석사논문은 Cox 모형 선택에서 **-2 log likelihood 변화**를 보고,
변수 추가/제거가 모형 적합도에 유의한 차이를 만드는지를 비교한다.

이걸 우리 문서에서 꼭 그대로 구현하지 않아도,
**“단순히 변수를 많이 넣는 것이 아니라 적합도와 해석 가능성을 함께 본다”** 는 메시지로 쓰기 좋다.

### 1-4. 비례위험 가정은 분석 전에 반드시 확인해야 함
논문은 Cox 모형을 쓸 때 **비례위험 가정 성립 여부를 먼저 검토해야 한다**고 명확히 적는다.

우리 프로젝트 문서에 넣기 좋은 표현:

> Cox 비례위험모형을 적용하기 전에는 공변량 간 위험비가 시간에 따라 일정하다는 비례위험 가정의 성립 여부를 점검해야 한다.

### 1-5. Cox와 Weibull 비교는 “왜 Cox를 택하는가” 설명에 도움 됨
논문은 Cox와 Weibull 비례위험모형을 비교하고,
결과가 비슷할 수 있지만 최종적으로 Cox 모형을 제시한다.

우리 프로젝트에 도움이 되는 해석은 다음과 같다.
- Weibull은 **기저위험함수 분포를 가정하는 모수적 접근**
- Cox는 **분포 가정을 덜 두는 유연한 접근**

즉, 발표/문서에서 이렇게 말하기 좋다.

> 본 프로젝트는 초기 단계에서 기저위험함수의 분포를 강하게 가정하기보다, 보다 유연한 세미파라메트릭 Cox 모형을 우선 채택한다.

### 1-6. 연속형 변수는 적절한 변환/구간화 검토가 필요할 수 있음
석사논문은 연속형 독립변수에 대해 **적절한 변수변환**을 고려했다고 강조한다.

이건 우리 프로젝트에서도 중요하다.
예를 들어:
- age를 그대로 넣을지
- mutation burden을 그대로 넣을지
- log transform, scaling, binning이 필요한지

문서화용 문장:

> 연속형 임상·유전체 feature는 선형성/해석 가능성을 고려하여 변환, 표준화 또는 구간화 여부를 검토한다.

## 2. 두 번째 PDF(LASSO-Cox 논문)에서 문서화할 만한 포인트
### 2-1. LASSO-Cox의 역할은 “예측변수 축소 + 과적합 완화 + 공선성 완화”
이 논문이 가장 직접적으로 주는 메시지는 이것이다.

> LASSO-based Cox regression은 변수 수를 줄이고, overfitting과 collinearity를 완화하는 데 유용하다.

우리 프로젝트에서는 이 문장을 거의 그대로 참고해도 된다.
다만 그대로 복사하지 말고 아래처럼 정리하는 게 안전하다.

> 유전자 feature 수가 환자 수에 비해 많은 상황에서는 LASSO-Cox를 이용해 예측에 기여하는 feature를 선별하고, 과적합 및 공선성 문제를 완화할 수 있다.

### 2-2. LASSO는 feature selection 단계, 최종 해석은 Cox 단계로 분리 가능
논문은 실무적으로 다음 구조를 취한다.
- 먼저 **LASSO-Cox로 변수 선택**
- 그 후 선택된 변수로 **Cox 회귀모형**을 구성

이건 우리 계획서와도 아주 잘 맞는다.
즉,
- 고차원 유전자 특징을 줄이는 단계: **LASSO-Cox**
- 최종 위험비와 해석을 제시하는 단계: **Cox model**

문서화용 문장:

> 본 프로젝트에서는 LASSO-Cox를 고차원 유전자 feature 선택 단계에 활용하고, 선택된 변수 집합을 기반으로 최종 Cox 모형을 적합하여 위험비와 해석가능성을 확보하는 방식을 고려할 수 있다.

### 2-3. 평가를 하나의 지표로 끝내면 안 됨
이 논문은 다음과 같은 평가 지표를 사용한다.
- calibration curve
- C-index
- AIC / BIC
- NRI / IDI
- timeROC / timeAUC
- DCA

우리 프로젝트에서 이걸 전부 다 쓰는 건 과할 수 있다.
하지만 문서화 관점에서는 다음 메시지가 중요하다.

> 생존예측모형 평가는 단일 지표에만 의존하지 않고, 구분능력(discrimination), 보정(calibration), 시간의존 성능, 임상적 유용성을 다각도로 검토하는 것이 바람직하다.

우리 프로젝트용 현실적 우선순위는 다음 정도가 적절하다.
- 1차: C-index
- 2차: Kaplan-Meier + log-rank
- 3차: calibration / time-dependent AUC

### 2-4. 내부검증과 외부검증을 구분하는 사고는 중요함
논문은
- 내부 코호트에서 모델 구성
- bootstrap 기반 내부 검증
- 외부 코호트에서 외부 검증

이라는 흐름을 쓴다.

우리 프로젝트는 당장 외부검증까지 어려울 수 있지만,
문서에는 최소한 이렇게 적어두는 것이 좋다.

> 모델 성능 평가는 학습 데이터 내부 교차검증 또는 bootstrap 기반 내부검증을 우선 수행하고, 가능하다면 독립 코호트 기반 외부검증으로 확장한다.

### 2-5. nomogram은 결과 시각화/서비스화 아이디어로 참고 가능
이 논문은 LASSO-Cox 기반 예측모델을 **nomogram** 으로 시각화한다.

우리 서비스에서 바로 nomogram을 넣을 필요는 없지만,
이 개념은 다음과 같이 연결 가능하다.
- 현재 서비스의 결과 카드
- 환자별 risk summary panel
- 입력 변수 기여를 시각적으로 정리하는 설명 화면

즉, 연구결과를 서비스화할 때 **“정량화된 예측을 시각적으로 설명하는 계층”** 이 필요하다는 힌트로 쓸 수 있다.

## 3. 우리 프로젝트에 직접 적용 가능한 정리
### 3-1. 추천 분석 파이프라인 문구
두 PDF를 합쳐 보면, 우리 프로젝트 문서에는 아래 파이프라인이 가장 자연스럽다.

1. 생존시간/이벤트 정의
2. 유전자 변이 feature 생성
3. 임상변수 결합
4. 단변량 Cox로 탐색
5. LASSO-Cox로 고차원 feature 축소
6. 선택된 변수로 다변량 Cox 적합
7. HR, 95% CI, p-value 해석
8. C-index, KM curve, log-rank 등으로 성능 평가
9. 가능하면 calibration 및 내부검증 추가

### 3-2. 문서에 바로 넣기 좋은 설명 문장
> 본 프로젝트는 먼저 유전자 변이 기반 feature와 임상변수를 구성한 뒤, 단변량 Cox 분석을 통해 후보 변수를 탐색하고, 고차원 feature 선택 단계에서는 LASSO-Cox를 활용하여 변수 수를 축소한다. 이후 선택된 변수 집합을 바탕으로 다변량 Cox 비례위험모형을 적합하여 각 변수의 hazard ratio와 신뢰구간을 해석한다.

### 3-3. “왜 LASSO를 쓰는가” 설명 문장
> 환자 수에 비해 유전자 feature 수가 많은 경우, 일반 Cox 모형만으로는 과적합과 공선성 문제가 발생할 수 있다. 이를 완화하기 위해 LASSO 기반 feature selection을 적용하고, 선택된 변수만으로 최종 Cox 모형을 구성하는 전략을 사용할 수 있다.

### 3-4. “왜 Cox를 최종모형으로 유지하는가” 설명 문장
> 최종 생존위험 해석 단계에서는 각 변수의 회귀계수와 hazard ratio를 직접 해석할 수 있는 Cox 비례위험모형이 임상적 설명 가능성 측면에서 유리하다.

## 5. 특히 도움이 되는 점 요약
### 첫 번째 PDF(석사논문)가 주는 도움
- Cox 모형의 **이론적 배경 정리**에 좋음
- **비례위험 가정**을 문서에 반드시 적어야 한다는 점을 강화함
- **단변량 → 다변량 → 최종모형 선택** 흐름을 정당화해 줌
- Weibull과 비교하면서 **왜 Cox를 택하는지** 설명하기 좋음

### 두 번째 PDF(LASSO-Cox 논문)가 주는 도움
- 고차원 feature 환경에서 **LASSO-Cox의 역할**을 설명하기 좋음
- **과적합/공선성 완화** 논리를 문서에 넣기 좋음
- 예측모델 성능평가를 **다지표로 봐야 한다는 점**을 보여줌
- bootstrap/internal validation 같은 검증 사고를 참고할 수 있음

## 6. 우리 프로젝트용 최종 권고
현재 프로젝트 문서/계획서 기준으로는 아래처럼 정리하는 것이 가장 좋다.

1. **최종 생존모형 설명의 중심은 Cox**
2. **고차원 유전자 feature 선택 단계는 LASSO-Cox**
3. **단변량 탐색 → 다변량 적합 → 최종 해석** 구조 유지
4. **비례위험 가정**은 문서에 반드시 명시
5. **C-index + KM/log-rank** 를 기본 평가세트로 두고, 가능하면 calibration/time-dependent 성능으로 확장
